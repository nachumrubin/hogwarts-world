Measurement method

Chromium WebGPU used SwiftShader. The host exposed no hardware GPU device. Pass times use asynchronous WebGPU timestamp queries around the complete studio render pass at 4× MSAA. Submit-to-fence time is a separate wall-clock observation of the same work. Copy/map and CPU canvas presentation follow that fence. Readback of the timestamp pair and the overdraw diagnostic are outside these intervals.

Macro views use LOD 0 at 1280 × 800 and report the median of two timed frames. Gameplay views use LOD 1 at 960 × 600 and the median of five. One unmeasured capture and one profiled warm-up precede each sample group. Compare within each pair. Results from this software adapter do not establish hardware frame rates.

¹ Vertex and index allocations contain the body and both wing configurations. Triangle counts reflect the displayed configuration. ² Draw counts include the studio floor. Each replacement adds one batched draw. Texture memory reports the incremental RGBA8 atlas allocation including mips; both versions use the E.2 1.33 MiB map. ³ CPU copy, buffer unmap and canvas update; compositor scanout was not measured.

A separate single-sample additive pass counts card footprints with depth rejection disabled. A second channel sums their filtered opacity. These quantify projected overlap and unused coverage; actual fragment invocations also depend on depth rejection and MSAA implementation. The close-up cards use more longitudinal sections and all atlases use mipmaps.

The existing hippogriff animation regression passed. The studies use the original skin palette, rig and motion. The visual comparisons use a frozen idle pose; moving-card shimmer is outside the evidence collected here.
